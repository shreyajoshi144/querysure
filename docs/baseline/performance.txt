  With KNOWLEDGE_SEARCH_MAX_CHUNKS=50000 the build took 7.1 s and the benchmark process peaked at about 1.2 GB (the index plus the test rows), so
  the default cap is 25,000 and only 4 workspaces' indexes stay in memory per process (KNOWLEDGE_INDEX_CACHE_WORKSPACES). The synthetic text uses a
  4,000-word vocabulary, which makes posting lists longer than real prose: expect real documents to be at least as fast.
  Memory (tracemalloc, same synthetic text): the 25,000-passage index holds about 285 MB and its build peaks near 520 MB, so a 512 MB instance
  (Render free) should lower KNOWLEDGE_SEARCH_MAX_CHUNKS to about 5,000.
  The index is rebuilt by the next question after a document is added or deleted (stamp = the workspace's document ids), also when another worker
  made the change. Each process builds its own copy.
